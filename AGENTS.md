# Инструкции для AI-агентов

Этот файл содержит правила разработки в репозитории **Zapusk**. Любой ИИ-ассистент обязан соблюдать их при генерации и редактировании кода.

## 1. Стек и инструменты
* **Язык:** Python 3.11+
* **GUI:** PySide6
* **Менеджер зависимостей:** `uv` (используйте `uv add <pkg>` и `uv run ...`, не создавайте `requirements.txt` вручную без необходимости).
* **Сборка и установка:** Nuitka через `Makefile` (`make`, `make standalone`, `make install`, `make clean`).

## 2. Архитектурные границы
* **Разделение слоев:** Вся бизнес-логика (запуск процессов, работа с Wine/Proton, анализ файлов) должна находиться строго внутри `zapusk/core/`. Модуль `zapusk/gui.py` отвечает только за отображение и вызов методов из `core/`.
* **Пути к ресурсам:** При обращении к файлам из `assets/` всегда вычисляйте путь относительно `Path(__file__).resolve().parent`, чтобы ресурсы корректно находились как при запуске через `uv run`, так и внутри собранного Nuitka-бинарника.
* **Интеграция с Wayland/X11:** В `gui.py` должны сохраняться `app.setApplicationName("zapusk")` и `app.setDesktopFileName("zapusk")` для корректного отображения иконки окна.

## 3. Запреты (Anti-patterns)
* **Никаких заглушек и «магии»:** Не создавайте фейковые модули, неработающие парсеры неэмулируемых платформ (PS5, Xbox Series) и скрипты, модифицирующие ядро ОС. Реализуйте только реально работающий функционал.
* **Не дублируйте сборку:** Не создавайте отдельные `.sh`-скрипты для установки или упаковки (`install.sh`, `build_all.sh`). Вся логика сборки и установки должна жить исключительно в `Makefile`.
* **Чистота репозитория:** Никогда не предлагайте коммитить директории `build/`, `dist/`, `.venv/` и скомпилированные бинарники.

## 4. Стиль кода и коммитов
* Пишите чистый, типизированный Python-код (используйте type hints).
* Предлагайте короткие сообщения коммитов в стиле **Conventional Commits** (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`).
